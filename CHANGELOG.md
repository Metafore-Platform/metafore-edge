# metafore-edge changelog

## Unreleased (development, v2) — the edge loads no route code

- **A route command that carries `route_yaml` is refused** (Compass f615b0a7, adr-060, adr-096). `RouteYamlRefusal` runs right after `ShellRefusal`: the key at the top level or in `parameters`, whatever the action and the value, answers `status: rejected`, `error: unsupported_payload` with a WARN line (action and route id only, never the YAML, which could embed SQL). The edge never loaded such a route; its only use of the YAML was `RouteYamlExtractor.extractQuery`, a text search for `query:` that fed the payload classifier. That method and its use in `handleExecute` are gone. The platform stopped sending `route_yaml` (metafore-api #1663), so this closes the door for an older core or a stray publisher. `RouteYamlRefusalTest` pins it.
- **The pinned `route_command` schema** is re-pinned to the metafore-api commit that drops `route_yaml` from it (`scripts/sync-contracts.sh`), and the contract test now refuses a command that carries it.

## Unreleased (development, v2) — the edge never logs a secret

- **`log/Redactor` and `log/CommandLog`** (Compass 9ece454f, step 1). `RouteExecutorRoute` logged every route command at INFO with `${body}`, so `db_user` and `db_pass` were written to the pod log (and, shipped from there, to CloudWatch) on every command. The arrival line now prints the command with the VALUE of every credential-shaped field replaced by `***`: a name containing `pass`, `pwd`, `secret`, `token`, `credential`, `apikey`, `auth`, `bearer`, `cookie`, `jwt`, `private` or `signature`, or having `key`, `user`, `username`, `login` or `uid` as a whole word, at any depth (objects and arrays) and also `user:password@` and `?token=` inside text values. The rest of the line is kept. Text that is not a JSON object is never printed; only its length is.
- Same treatment for the write-back arrival line (`RestAdapterRoute`), the REST call lines (URL and exception message), the file-feed declaration and URI lines, and the data-source registration failure message.
- **A malformed command no longer quotes itself.** The three command routes (`RouteExecutorRoute`, `RestAdapterRoute`, `DiscoveryRoute`) read the command with `Redactor.parse`, a mapper with Jackson's `INCLUDE_SOURCE_IN_LOCATION` off: its parse error used to repeat the first characters of the input, which is the credentials. A well-formed command parses exactly as before.
- `RedactorTest` pins the above, including that the arrival line holds no trace of a canary `db_pass`/`db_user`, and a source scan that fails if a Camel `.log(...)` step prints the body or headers. **Not changed:** the command still carries the credentials (adr-091 phase 2 removes them from the payload; Compass 9ece454f step 2), and passwords already in past logs need rotating (step 3).

## Unreleased (development, v2) — more source databases, part 2b: the read patterns

- **`read` (by_id, by_ids, list with keyset pagination, count, and the ADR-077 `where_conditions`) runs on MySQL and MariaDB** (Compass 0e4dda60): `DialectExecutor.executeRead` and `DialectReadSql`. The payload is parsed and checked by the new `ReadRequest`, **moved unchanged out of `SqlExecutor.executeParametricRead`** (SqlExecutor shrinks by 168 lines) so every database refuses a payload in the same order with the same message; the Postgres path calls it too and its behaviour is unchanged. The statement shapes, bind order (keyset comparator, filter value(s), predicate values, page size) and replies (`has_more`, `last_keyset_value`, `{count: N}`) are the Postgres ones; the page cut-off, the case-insensitive `contains` and the count alias are the dialect's. An Oracle table is rendered as the catalog resolved it, never renamed by a column mapping.
- **`DialectGate`** lets `read` through for MySQL and MariaDB. SQL Server and Oracle (code and golden strings are here) stay gated until their live jobs pass. `DialectParametricIT` covers every pattern, `contains`, `between`, `in`, `is_not_null`, tombstone exclusion and a three-page keyset walk against live MySQL 8.4 and MariaDB 11.4.

## Unreleased (development, v2) — more source databases, part 2: create / update / delete / select

- **`service/DialectExecutor`** runs the four parametric operations on MySQL, MariaDB, SQL Server and Oracle (Compass 0e4dda60): the same checks in the same order, the same messages and the same reply as the Postgres path, which is unchanged. Tables and columns are checked in the catalog (`DialectCatalog`: INFORMATION_SCHEMA; Oracle's ALL_TABLES / ALL_VIEWS / ALL_TAB_COLUMNS, with `db/OracleNames` resolving the platform's lower-case names to the stored spelling and showing stored upper-case names in lower case). `DialectStatements` builds the SQL in the source's dialect: identifiers quoted by `Dialect.quote` (an embedded closing quote doubled), every value a `?` bind parameter, no value ever concatenated. `DialectBinder` binds ISO dates and timestamps as `java.time` objects (a zoned value landing in a wall-clock column is normalised to UTC), everything else as `SqlExecutor.bindValue` does. A session is set to UTC (and Oracle's decimal separator) per connection. `db_type=mysql` connects over TLS without verifying the server's certificate (MySQL 8's default login needs TLS or an RSA key exchange; found by the live job); `mariadb` connects as it is.
- **`DialectGate`** now lets `create`, `update`, `delete` and `select` through for MySQL and MariaDB, the types proven against a live server; SQL Server and Oracle keep the gate until their live CI jobs pass (their dialect code and golden strings are here, no traffic is routed to them); `read`, `write_with_events` and `introspect` stay refused off Postgres until their own PRs. `connect_and_ping` stays refused until its probe lands.
- **CI job `dialects`** (`DialectParametricIT`) runs the operations against a real MySQL 8.4 and MariaDB 11.4. SQL Server and Oracle jobs follow.

## Unreleased (development, v2) — more source databases, part 1: types, dialects, pools

- **Add `db/DbType`, `db/Dialect`, `db/DataSources`** (Compass 0e4dda60, adr-059). A command's `db_type` (`postgresql` default, `mysql`, `mariadb`, `mssql`/`sqlserver`, `oracle`) picks the JDBC driver (MariaDB Connector/J for both MySQL and MariaDB, mssql-jdbc, ojdbc11), the default port and the dialect's SQL fragments (quoting, page limit, case-insensitive contains, count alias; the Go agent's `dialect.go` is the reference). Timeouts match the Postgres pool; the password is never in the URL.
- **`DataSourceRegistry`** registers a pool per type; the type is part of the fingerprint, and a non-Postgres key carries it (`conn:mysql:...`) while a Postgres key is unchanged. **`RouteExecutorRoute`** reads `db_type` and answers an unknown one with an error result `Unsupported db_type: <name> (expected ...)`. Operations still run Postgres SQL until part 2's next PR. Until then **`db/DialectGate`** refuses every operation and `connect_and_ping` for a non-Postgres `db_type` with `dialect not yet supported for <operation> (db_type <x>)` (`error_details: dialect_not_supported`), so Postgres SQL never runs against another kind of server; each later PR lets one operation through per dialect.

## Unreleased (development, v2) — per-edge reply topic

- **Add `topic/ReplyTopic`** (Compass 9a26adcd, adr-059). A command's `response_topic` is answered on only when it is this edge's own per-edge topic: `response/<tenant>/<controller>/` compared exactly, then an id of `[A-Za-z0-9._-]{1,128}` (an allowlist: no wildcard, no further level, no `?` or `&` that Camel would read as endpoint options, no space or control character). The retired shared `response/<id>`, another edge's topic and anything malformed are not answered on (logged at WARN); the result still goes to its telemetry topic. The broker would refuse such a publish anyway (an edge may publish only under `response/<its username>/`).
- **`RouteExecutorRoute`, `RestAdapterRoute` (write-back) and `DiscoveryRoute`** publish the result to the command's valid reply topic (through a fixed endpoint with the topic as the `CamelPahoOverrideTopic` header, never an endpoint URI built from the command) as well as to `telemetry/.../route-results` (`.../discovery`). The discovery route used to echo to any topic the command named. The result is converted to one String before the two publishes so both carry it in full.

## Unreleased (development, v2) — an mTLS integration test against the platform's own broker

- **Add `scripts/mtls-broker.sh`, `tests/mtls/` and `MqttMtlsIT`** (Compass 9a26adcd). CI job `mtls` of `development.yml` starts EMQX 5.8 with the platform chart's own `emqx.conf` and `acl.conf` (pinned byte for byte from metafore-api by `scripts/sync-broker-config.sh`; `BrokerConfigPinTest` fails offline on a hand edit) plus the chart's certificate listener (`tests/mtls/mtls.overlay.conf`), makes throw-away certificates with openssl, and runs the edge's real `MqttSecurity` against it: the broker names the client by its certificate's common name on `ssl:default`; the topic rules confine it; a stranger's certificate, no certificate and an untrusted broker are refused; the same factory presents whatever is on disk at the next connect. Runs on `development` only; `mvn verify` locally skips it unless `MTLS_DIR` is set.

## Unreleased (development, v2) — MQTT sign-in: the edge never connects anonymously

- **Add `mqtt/MqttSecurity` and `mqtt/ReloadingSslSocketFactory`** (Compass 9a26adcd, adr-059). The edge signs in to the broker with its client certificate (`METAFORE_MQTT_TLS_ENABLED`, `_CA_CERT`, `_CERT`, `_KEY`: PEM files, normally mounted at `/etc/metafore/mqtt`) and sends **no username and no password**: the broker maps the certificate's common name, which must be `<TENANT_ID>/<CONTROLLER_ID>`, to the username its topic rules key on. The pair is read again at every connect, so a certificate the platform renews on disk is used without a restart; a pair caught mid-rotation keeps the last one that loaded. PKCS#8, SEC1 and PKCS#1 keys load (bcpkix).
- **Without a certificate**, `METAFORE_MQTT_USERNAME` (exactly `<TENANT_ID>/<CONTROLLER_ID>`) and `METAFORE_MQTT_PASSWORD` are required. **An edge with neither does not start** (before, it connected anonymously). `METAFORE_MQTT_TLS_INSECURE` is refused.
- `AccessController` registers one `paho` component with these settings; every route's endpoint inherits them. No route URI changed.

## 1.1.0 — 2026-05-16 — Phase 14.9 edge topology advertisement

- **Add `EdgeRuntime` enum** (`docker | native | docker-host-network | unknown`) classifying the surrounding process topology. Wire form is kebab-case (matches `contracts/mqtt/registration.schema.json` enum).
- **Add `RuntimeProbe`** — layered auto-detection (`EDGE_RUNTIME` env override → `/.dockerenv` file → `/proc/1/cgroup` markers → `HOSTNAME` heuristic → host-network upgrade via `/proc/net/dev` → JVM `os.name` fallback → `UNKNOWN`). Injectable `Probes` record makes the probe unit-testable without spelunking the host filesystem.
- **Extend `EdgeConfig`** with `runtime()` + `runtimeHints()` accessors. The probe runs once at construction; result is cached. Hints whitelist 5 keys (`os_name`, `java_version`, `hostname`, `docker_env_file_present`, `cgroup_signature`) — no env-var dump.
- **Extend `MessageFactory.registration`** with a 7-arg overload taking `runtime` + `runtimeHints`. The legacy 5-arg overload is preserved; it omits both fields (back-compat invariant — older payloads still validate against the additive schema).
- **`RegistrationRoute`** now passes `config.runtime()` + `config.runtimeHints()` so every edge registration MQTT payload advertises its topology.
- **Bump `EDGE_VERSION`** default `1.0.0 → 1.1.0` to signal the additive wire-protocol extension. No client-side gating; older cores ignore the new fields.

Anchor incident: 2026-05-16 — a Source authored against `host.docker.internal` survived an AC restart that switched from Docker to native Java; the JDBC connection silently failed because `host.docker.internal` is a Docker-engine hosts-file alias that doesn't exist on a native Windows JVM. Surfacing the runtime as part of registration lets metafore-core flag the topology mismatch at mount time (see brief `BRIEF_PHASE_14_9_EDGE_TOPOLOGY_ADVERTISEMENT.md`).

Pairs with `mount-test-before-commit` (Brief 14.12) — Phase 14.9 produces the runtime signal that 14.12's pre-commit connectivity check consumes.
